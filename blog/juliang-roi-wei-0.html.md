## 为什么「ROI 全 0」是个重要信号

先想清楚一件事：ROI 为 0 和 ROI 很低，是两种完全不同的情况。

| 情况 | 含义 | 该查什么 |
|---|---|---|
| ROI 很低（比如 0.3） | 投放效率问题 | 出价、定向、素材 |
| ROI 精确为 0 | 要么没有付费用户，要么数据没回传 | 先查回传链路 |

如果账户有激活、有消耗，但 ROI 精确为 0，更大的概率是数据链路问题——用户付费了，但这个「付费」事件没有回传给广告平台。

- **0** — 所有 ROI 指标值（小程序 ROI 系列全为 0）
- **9** — 近 14 天激活数（有转化，不是没人用）
- **444** — 近 14 天点击数（有流量，链路前端是通的）
- **¥19.67** — 激活成本（说明投放本身在工作）

## 回传断了会发生什么（连锁反应）

这不是「数据不好看」的问题，它会真实地影响投放效果：

1. 模型学不到「谁会付费」：巨量的自动投放依赖转化数据来学习人群。收不到付费回传，模型只能按「激活」优化，而激活的人未必会付费。
2. 出价失去依据：你无法用付费价值来指导出价，只能按激活成本出价，很容易出高。
3. 量级起不来：转化数据稀疏 → 模型学习慢 → 不敢放量 → 消耗上不去。这解释了「有钱花不出去」。
4. 所有优化动作都失去判断标准：你到底该提价还是降价、该收窄还是放开，都没有依据。

> **要点｜一句话总结**
> 回传断了，你不是在「优化投放」，你是在盲投。
> 这时候任何基于 ROI 的决策都是错的——因为分子是 0。

## 怎么确认回传是通的（四步）

1. **看指标名对不对** —— 小程序类落地页有一套专门的归因指标，命名带 attribution_ 前缀，比如：attribution_micro_game_0d_roi、attribution_micro_game_7d_roi。如果你拉的是普通 ROI 字段，可能压根拿不到数据。
2. **确认「优化目标」与回传事件是否匹配** —— 如果优化目标是「激活」，但你想看付费 ROI，那就需要确认付费事件确实被回传了——两者是不同的事件。
3. **检查回传 URL 的占位符是否被正确替换** —— 巨量的回传 URL 里有多个宏参数需要被替换成实际值：
```
https://你的监测域名/callback
  ?promotionid=__PROMOTION_ID__
  &ip=__IP__
  &callback=__CALLBACK__
  &event_type=__EVENT_TYPE__

# 如果服务端没做替换，回传的就是字面量，等于废数据
```

4. **看服务端有没有收到回传请求** —— 登录你自己的监测服务器，看访问日志里有没有来自巨量的回传请求。这一条最直接——有请求说明链路通，没请求说明链路断。
## 一个我犯过的判断错误（值得记下来）

看到 ROI 全 0 之后，我的第一个结论是：「回传事件和优化目标不匹配 → 模型学不会 → 所以量起不来」。听起来很有道理。

但复查数据后发现这个结论是错的——回传口径其实是对的。真正的原因是：预算池本身很小，已有的数据量不足以支撑模型学习。

> **注意｜⚠️ 这个教训很值钱**
> 「数据异常」的归因有多个可能，先验证再下结论。
> 反直觉的是：回传没问题时，「量起不来」的原因可能只是数据量太小。
> 小预算下，模型的统计显著性本来就不足——这不是 bug，是数学。

## 所以正确的顺序是

1. **先确认回传链路（上面的四步）** —— 这一步花十分钟，但能排除掉最大的可能性。链路不通的话，后面做什么都是盲投。
2. **再确认数据量是否足够** —— 如果日消耗只有几十块、激活只有个位数，那数据量本身就不足以让模型学习。这时候的问题不是「优化」，而是「量级」。
3. **然后才轮到优化投放** —— 链路通了、数据量够了，再看出价、定向、素材——这时你的优化才有依据。

## 常见问题

### 巨量引擎所有 ROI 指标都是 0，是什么原因？

ROI 精确为 0 通常是数据链路问题而非投放问题。可能是付费回传没打通（用户付费了但事件没回传），也可能是拉取的指标名不对——小程序类落地页的归因指标带 attribution_ 前缀，如 attribution_micro_game_0d_roi。建议先确认服务端有没有收到来自巨量的回传请求。

### 怎么确认广告转化回传是否正常？

四个检查点：一看指标名是否正确（小程序类用 attribution_ 系列）；二看优化目标与回传事件是否匹配；三看回传 URL 里的宏参数（promotionid、ip、callback、event_type）是否被服务端正确替换，未替换会回传字面量；四看自己的监测服务器日志里有没有收到回传请求。

### 回传没问题但量还是起不来怎么办？

如果确认回传正常，那要检查数据量是否足够。日消耗很低时（例如几十元）、激活数只有个位数，模型缺乏统计显著性，学习本身就慢。这时问题不是优化技巧，而是量级——需要先解决预算与出价竞争力问题。
