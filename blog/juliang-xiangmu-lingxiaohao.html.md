# 项目状态正常但消耗永远是 0？查一下有没有单元

> 巨量引擎是「项目 → 单元 → 素材」三层结构，只建了项目没建单元就没有可投放实体。我那个账户 40 个项目里 35 个是废弃空壳，项目状态显示 ENABLE 却永不消耗。附排查方法与批量清理顺序。

- 发布日期：2026-09-18
- 阅读时长：约 7 分钟
- 数据说明：数据来自我方自营微信小程序广告账户，已脱敏

这是我踩过的最隐蔽的一个坑。项目建好了，状态显示正常，后台里看着和能跑的计划一模一样——但消耗永远是 0。查了很久才发现：我只建了项目，没建单元。

## 巨量引擎的三层结构

把这件事说清楚只需要一张图：

```
项目（campaign）      ← 决定目标、预算、投放模式
  └─ 单元（unit）     ← 决定定向、出价、素材
       └─ 素材        ← 视频 / 图文 / 标题

只建到项目层 = 没有可投放实体 = 消耗永远为 0
```

> **注意｜⚠️ 状态字段会误导你**
> 项目状态显示 ENABLE（已启用），这是真的——它确实启用了。
> 但没有单元，系统就没有东西可以投出去。
> 「启用」不等于「在跑」。这是最容易误判的地方。

- **35** — 废弃空壳项目数（单个账户共 40 个项目）
- **87%** — 空壳占比（大部分精力被无效项目占用）
- **5** — 真实在投项目数（40 个项目里只有这些在跑）
- **0** — 空壳项目的消耗（看起来正常，实际从不花钱）

## 为什么会有这么多空壳

1. 批量建立计划时只建了一层：我在做批量建计划时，把「项目 → 单元 → 素材」的流程做成了两次调用，但第一次调用失败后没有正确中断，于是留下了一批只有项目的半成品。
2. 复制计划时只复制了项目：复制是常用操作，但如果只复制到项目层，新项目同样没有单元。
3. 废弃测试计划没清理：早期测试留下的项目没删，时间久了就堆积成一片空壳。

## 怎么排查（三步）

1. **数单元，不数项目** —— 在 竞价投放 → 搜索 → 单元 里看单元总数。如果单元数远少于项目数，差额就是空壳。
2. **按消耗排序** —— 把项目按消耗排序，长期为 0 的一律标记为可疑。注意：新项目短期内为 0 是正常的（还在学习期），要看创建时间。
3. **逐个确认项目下有没有单元** —— 点进可疑项目看它的单元列表。空的话就是这个问题。
## 清理顺序建议

确认了有空壳之后，别急着一次全删。我用的是这个顺序：

- 先补齐有潜力的项目：如果某个项目本身配置合理（定向、出价都没问题），只是缺单元，那就补上单元而不是删掉。
- 再删纯废弃项目：早期测试留下的、配置已经过时的，直接清理。
- 最后建检查机制：把「项目下是否有单元」加进日常检查项，避免再堆积。

> **说明｜为什么空壳项目有害，不只是「占地方」**
> 它们会污染你的判断：你以为在投 40 个计划，实际只有 5 个在跑。
> 基于错误的前提做决策，方向必然错。
> 我第一次诊断自己账户时就得出了「账户规模不小」的错误结论。

## 常见问题

### 巨量引擎项目状态正常但消耗为 0 是什么原因？

最常见的原因是只建了项目没建单元。巨量引擎是「项目 → 单元 → 素材」三层结构，没有单元就没有可投放实体。项目状态会显示 ENABLE，看起来正常，但消耗永远是 0。建议到单元列表核对单元数是否与项目数匹配。

### 怎么快速排查账户里有多少空壳项目？

直接在单元列表看单元总数，与项目数对比，差额通常就是空壳。也可以把项目按消耗排序，排除新建项目后，长期为 0 的基本都是这个问题。注意新项目在学习期内消耗为 0 属正常。

### 空壳项目应该删掉还是补齐？

分情况。如果项目本身配置合理（定向、出价、关键词都没问题），只是缺单元，补齐单元比删掉更有价值；如果是早期测试留下的废弃项目，直接清理。清理建议分批进行，先补有潜力的、再删纯废弃的。
